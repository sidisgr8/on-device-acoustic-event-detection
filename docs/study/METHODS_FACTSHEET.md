## 1. Data and the shared pipeline

### 1.1 Dataset
* UrbanSound8K, Zenodo record 1203745, CC BY-NC 4.0; archive MD5 `9aa69802bbf37fb986f71ec1483a196e` verified.
  8,732 WAV clips, 10 classes, 10 predefined folds (806 to 990 clips per fold). *(measured, results/eda/eda_stats.json)*
* Class counts: gun_shot 374, car_horn 429, siren 929, the other seven 1,000 each. 1,297 source (Freesound) recordings.
* Clip lengths: 7,333 clips are 4 s (84 %); 1,399 are shorter (457 under 1 s); 8 are marginally longer (max 4.037 s).
  Short clips concentrate in a few classes: gun_shot 96 % short, car_horn 53 %, dog_bark 32 %, drilling 20 %, jackhammer 20 %,
  and about 0 to 4 % for air_conditioner, children_playing, engine_idling, siren, street_music.
* Native audio: sample rates 8 to 192 kHz (44.1 kHz: 5,370; 48 kHz: 2,502; 96 kHz: 610; 233 clips at 32 kHz or below);
  7,993 stereo and 739 mono; PCM16, PCM24, float32, 8-bit and ADPCM.

### 1.2 Clip processing (`src/data/cache.py`, `src/features/params.py`)
1. Read with `soundfile` as float32; mix channels to mono by **averaging**.
2. Resample to **16 kHz** with `librosa.resample` (default `soxr_hq`, band-limited, so anti-aliased).
3. Fix to **4.0 s = 64,000 samples**: crop to the first 4 s if longer, otherwise **zero-pad at the end**. No peak or loudness
   normalisation (absolute level is kept).
4. Bookkeeping per clip (`data/cache/index.csv`): original sample rate and length, number of real 16 kHz samples,
   `padded`, `cropped`, `n_valid_frames`. 1,399 clips padded, 8 cropped.
5. Caches (gitignored, `data/cache/`): waveforms (8732x64000 float32), raw log-mel (8732x128x201), AST fbank (8732x400x128).

### 1.3 Log-mel features for the CNN family (`src/features/logmel.py`)
* `librosa.feature.melspectrogram(sr=16000, n_fft=1024, hop_length=320, n_mels=128, fmin=20, fmax=8000, power=2.0, center=True)`
  (librosa defaults otherwise: Hann window, Slaney mel scale and normalisation), then `power_to_db(ref=1.0, amin=1e-10, top_db=None)`.
* n_fft 1024 = 64 ms window (15.6 Hz bin spacing); hop 320 = 20 ms; `center=True` gives 1 + 64000/320 = **201 frames**; input tensor (1, 128, 201).
  fmax 8000 Hz is the Nyquist frequency of 16 kHz audio.
* Digital silence (the zero padding) maps to 10 log10(1e-10) = **-100 dB**.
* **dB floor (D-15): values are clamped from below at -80 dB** at load time (the cache keeps the raw values). Rule: the highest multiple
  of 10 dB that clamps at most 1 % of the real (non-padded) time-frequency bins of the round-1 training folds (3 to 10); clamped fractions
  were 0.00 / 0.24 / 0.58 / 1.35 / 3.34 % for floors -100 / -90 / -80 / -70 / -60 dB. Real content: median -24 dB; padding sat 4.4 sigma below
  the mean before the clamp and 3.3 sigma after it. (`results/eda/db_floor_analysis.json`, decided from audio statistics only.)
* **Normalisation (D-16):** one scalar mean and one scalar std, computed from the **training folds of the round only** and only over **real
  (non-padded) frames**, then applied to train, validation and test. Example, round 1: mean -24.22 dB, std 17.15 dB.

### 1.4 AST features (`src/features/logmel.py: ast_fbank`, D-18)
* `torchaudio.compliance.kaldi.fbank(sample_frequency=16000, window_type="hanning", num_mel_bins=128, htk_compat=True, use_energy=False,
  dither=0.0, frame_shift=10)` (25 ms default frame length): 398 frames for 4 s, zero-padded **in fbank space** by 2 frames to **400**.
  Identical to `transformers.ASTFeatureExtractor(max_length=400)` (unit test, atol 1e-4).
* Normalised with the checkpoint's constants: (x - (-4.2677393)) / (2 x 4.5689974). No statistics are estimated from any fold.
* So there are **two front-ends**: log-mel (librosa, 64 ms window, 20 ms hop, 128 mel bands 20-8000 Hz, dB with floor) for the CNN family and
  Kaldi fbank (25 ms window, 10 ms hop, 128 bins) for AST. The synopsis speaks of a "common" log-mel front-end; this is the one deliberate difference.

### 1.5 Augmentation (`src/data/dataset.py: SpecAugment`)
* SpecAugment-style masking only (no time warping, no waveform augmentation), **training batches only**: 2 frequency masks of width
  uniform in {0..16} bins and 2 time masks of width uniform in {0..20} frames (CNN family) or {0..40} frames (AST), both up to 400 ms (D-36); start positions uniform; independent per sample.
  Masked values are set to 0, which equals the data mean after normalisation. Applied on the (B,1,F,T) tensor for the CNN family and on (B,T,F) for AST.
* The module is the identity unless `.train()`; the training loop switches it on only inside the training epoch; `evaluate()` never receives it (unit-tested).
* Masks come from a CPU generator seeded with 42 x 1000 + epoch (reproducible and resumable).
* The time-mask limit is expressed in seconds, not frames: 20 frames x 20 ms hop = 400 ms (CNN family) and 40 frames x 10 ms shift = 400 ms (AST). Decided by the owner before any AST result existed (D-36).

### 1.6 Split rule (`src/data/splits.py`)
Round k = 1..10: **test = fold k, validation = fold (k mod 10) + 1, train = the other 8 folds.** Round 10 validates on fold 1.
Folds are never re-split. Round 1 sizes: 6,971 train / 888 validation / 873 test clips.
Model selection uses the validation fold; the test fold is evaluated **once per round**, with the best-validation checkpoint
(the result file is created in exclusive mode `"x"`).

## 2. Common training protocol v2 (`src/train/loop.py`, configs, D-26)

| item | CNN baseline | MobileNetV3-S scratch | MobileNetV3-S ImageNet | CRNN | AST |
|---|---|---|---|---|---|
| learning rate | 1e-3 | 1e-3 | **3e-4** | 1e-3 | **5e-5** |
| batch size | 64 | 64 | 64 | 64 | **16** |
| epochs | 30 fixed | 30 fixed | 30 fixed | 30 fixed | **5 fixed** |
| warm-up | 2 epochs linear | 2 | 2 | 2 | none |
| early stopping | none | none | none | none | none |
| optimiser | AdamW (wd 0.01, default betas) | same | same | same | same |
| loss | cross-entropy, label smoothing 0.1 | same | same | same | same |
| precision | fp32 | fp32 | fp32 | fp32 | chosen automatically (fp32 / fp16 / bf16) by `amp_probe`, D-27/D-28 |
| input | log-mel 1x128x201 | same | same | same | fbank 400x128 |
| max time-mask width | 20 frames (400 ms) | 20 frames (400 ms) | 20 frames (400 ms) | 20 frames (400 ms) | **40 frames (400 ms)** |
| seed | 42 | 42 | 42 | 42 | 42 |

Details that apply to all models:
* **Scheduler:** per optimiser step. Warm-up: lr x (step+1)/warm-up steps; then half-cosine down to **0 at the last step of the last epoch**
  (cosine is defined over exactly the fixed epoch count). Steps per epoch = train clips // batch (training drops the last incomplete batch):
  108 for round 1 with batch 64 (6,971 // 64), 435 with batch 16.
* **Weight decay** 0.01 is applied by AdamW to all parameters (including biases and normalisation parameters).
* **Label smoothing 0.1:** PyTorch's `CrossEntropyLoss(label_smoothing=0.1)`; the reported validation/test loss uses plain cross-entropy.
* **Model selection:** best validation accuracy over epochs (strictly greater replaces, so ties keep the earlier epoch); weights saved to
  `checkpoints/<exp>/fold<k>/best.pt` (+ `best.json`). Training accuracy in the logs is measured on augmented batches with dropout on.
* **Randomness:** `torch.manual_seed(42)` at the start of each fold; shuffling uses a generator seeded by 42 x 100003 + epoch; dropout and masks are reseeded
  every epoch from (42, epoch), so a resumed run follows the same random stream. Only **seed 42** is used (no seed repeats).
* **Metrics:** accuracy; macro-F1 = unweighted mean of the 10 per-class F1 scores (scikit-learn, labels 0..9, `zero_division=0`) per test fold; per-class F1;
  confusion matrix (rows = true class); accuracy on padded vs full-length test clips. Tables report mean +/- **sample** std (ddof = 1) over the folds listed.
* **Protocol v1** (up to 40 epochs, patience-8 early stopping, cosine over 40) was used for one aborted CNN fold-1 run and is superseded (D-26);
  its files are in `results/superseded_protocol_v1/` and are never used. The fold-1 test accuracy of that run had been seen before the change was decided.
* Run-time facts (measured on the Apple M5, MPS): about 14.0 s/epoch for the CNN baseline (fp32, batch 64); MobileNetV3-S 9.6 s; CRNN 14.4 s.

### 3.1 Per-model facts and decisions

**CNN baseline** (`src/models/cnn.py`; no model-specific deviations beyond the shared protocol). 4 blocks of Conv2d 3x3 (padding 1, no bias) - BatchNorm2d - ReLU - MaxPool 2x2,
channels 1 to 32 to 64 to 128 to 256; the feature map goes 128x201 to 8x12; global average pooling over frequency and time; Dropout 0.3; Linear 256 to 10.
Default PyTorch initialisation. 390,890 parameters; about **361 M multiply-accumulates per clip**: block 1 contributes only ~7 M, but blocks 2, 3 and 4 contribute ~118 M each (channels double while the resolution halves,
so the cost per block stays constant). Few parameters, but not few operations: roughly 12x the MACs of MobileNetV3-Small.

**MobileNetV3-Small, scratch and ImageNet** (`src/models/mobilenet.py`, D-25). timm `mobilenetv3_small_100`, `in_chans=1`, 10-way classifier, head dropout 0
(timm default `drop_rate`). 1,527,818 parameters, about 28.6 M MACs. For the ImageNet run the weights are timm `lamb_in1k`
(HuggingFace `timm/mobilenetv3_small_100.lamb_in1k`, file sha256 `46d2c063b18125884c48937afa4c49e18128869e52e8db96df48bf0a4d7ff697`, also stored in each
result's `model_provenance`); timm builds the 1-channel stem by **summing the three pretrained RGB filters** (unit-tested numerically). Inputs are
standardised log-mel values, **not** ImageNet-normalised RGB. The ImageNet run also uses lr 3e-4 instead of 1e-3, so it differs from the scratch run in
initialisation *and* learning rate (as the spec prescribed).

**CRNN** (`src/models/crnn.py`, D-24). Three conv blocks (Conv 3x3 - BN - ReLU - MaxPool) with channels 32/64/128 and pooling (2,2), (2,2), (2,1) over
(frequency, time): (128,201) to (16,50). Per time step the 128 channels x 16 frequency bins are flattened to **2,048**, projected by a plain Linear to 128 (no
activation), passed through a **single-layer bidirectional GRU, hidden 128** (output 256 per step, 50 steps), then **[mean over time ; max over time] = 512**,
Dropout 0.3, Linear 512 to 10. 558,442 parameters (GRU 198,144; projection 262,272). The spec's shape claims (16, 50, 2,048) were verified on the real input.

**AST** (`src/models/ast.py`, D-08, D-18, D-22, D-27). HuggingFace `ASTForAudioClassification` with the architecture of the AudioSet checkpoint
`MIT/ast-finetuned-audioset-10-10-0.4593` (snapshot `f826b80d28226b62986cc218e5cec390b1096902`, weights file sha256
`ae0c1e2ad4e1381d851fa9bf298ba13ebc9c5a914cdee2dbe427a6583869924d`). 12 transformer layers, hidden 768, 12 heads, MLP 3072, 16x16 patches with stride 10 in both axes
(overlap 6), hidden and attention dropout 0.0. Input 400 frames x 128 mel bins gives 12 (frequency) x 39 (time) = 468 patches; plus the class and distillation
tokens = **470 tokens**. Output: the two special tokens are averaged, `(tok0 + tok1) / 2`, then LayerNorm and a new Linear 768 to 10 (the 527-way AudioSet head is replaced).
85,625,098 parameters; about 40.0 G MACs in Linear/Conv layers + 4.1 G in the attention matmuls (analytic) = **about 44 G MACs per clip**.
* **Position embeddings (D-08/D-22).** The checkpoint was trained for 1024 frames: a 12 x 101 patch grid, embedding tensor (1, 1214, 768). Input length 400 needs a
  12 x 39 grid, tensor (1, 470, 768). HuggingFace would re-initialise it, so it is cropped by hand as in the AST authors' code: the 2 special-token embeddings are kept,
  the 1212 patch embeddings are reshaped to (12, 101, 768), **all 12 frequency rows are kept and time columns [31, 70) (centred crop) are taken**, and they are flattened
  back to 468 tokens. This reshape assumes token index = freq_idx x T + time_idx; verified by an impulse test (an impulse at time frame 5 / mel bin 125 changes exactly token
  429 = 11 x 39 + 0). Unit tests check shapes, that cropped values equal the checkpoint slice, and that the other 200 pretrained tensors are loaded bit-identically.
  `pos_crop: first` would take columns [0, 39); the owner chose the authors' centred crop (D-22).
* **Pretraining lineage (from the AST paper, verified in `REFERENCES_VERIFIED.md`):** DeiT (ImageNet) initialisation, then AudioSet fine-tuning; this checkpoint is therefore
  "ImageNet + AudioSet". Fine-tuning here: lr 5e-5, batch 16, 5 epochs, cosine to 0, no warm-up, same SpecAugment, best-validation epoch.
* **Precision:** decided by the queue's `amp_probe` (30 optimiser steps per mode on fold-1 training clips only; rule fixed in advance in D-27); the outcome is recorded as D-28 and in `results/ast_amp_probe.json` when it has run.

### 3.2 Compressed variants (`src/compress/`, scripts `quant_eval.py`, `prune.py`; D-09, D-10, D-31, D-33)
* **Post-training int8 quantization, no retraining.** Calibration data: 100 clips from the **training folds** of the round (fixed seed 42).
  * PyTorch static (FX graph mode, qnnpack) for CNN and MobileNetV3; PyTorch dynamic for Linear (+GRU) in the CRNN and Linear in AST. Static-quantized models are saved as TorchScript
    (a pickled FX-quantized module cannot be reloaded in this torch).
  * ONNX Runtime: export (opset 17), **fp32 ONNX must match PyTorch within 1e-3 max logit difference before quantizing**; int8 = ORT static QDQ (conv models) or ORT dynamic (CRNN, AST).
    ORT has no dynamic int8 for GRU, so the CRNN's GRU stays float32 there.
  * A variant that fails to build is stored as an error finding. Size and accuracy are always reported separately from latency.
* **Pruning:** global magnitude (L1), unstructured, 30/50/70 % (AST 30/70 %), folds 1/5/9. Prunable = Conv2d, Linear and GRU weights (not biases, norm parameters, embeddings; the classifier head is
  pruned). One global threshold; explicit masks re-applied after each optimiser step. Fine-tune 3 epochs at 0.1 x the original lr, cosine, no warm-up, best of 3 epochs by validation accuracy, test once.
  Reported: non-zero parameters, gzip(9) size of the saved weights, accuracy, macro-F1. Unstructured sparsity does not reduce CPU latency.
* **Latency (not yet run):** batch 1, one 4 s validation clip, CPU only, 20 warm-up + 200 timed runs, median and p95, 1 and 4 threads, feature extraction timed separately, fold-1 weights,
  all variants. The tool refuses to run unless the machine is idle (no job processes, 1-minute load average <= 1.0). Machine: Apple M5, 4 performance + 6 efficiency cores; macOS gives no core affinity.

## 5. Known limitations and caveats (facts, for honest discussion)

1. **Source leakage across folds (small).** Folds are grouped by Freesound recording, but 5 of the 1,297 recordings (fsID 77751, 106905, 132016, 176638, 180937) have clips in more than one fold
   (always as different classes cut from the same file). Official split kept. *(results/eda)*
2. **Padding and clip length are detectable and class-correlated.** 96 % of gun_shot clips are padded versus about 0 % for several classes; the -80 dB clamp only moves padding from 4.4 to 3.3 sigma below the mean.
   Predicting the class from **non-acoustic metadata alone** (sample-rate group, channels, sample format, duration; random forest, official 10-fold CV) reaches **19.9 %** vs 10 % chance and 11.5 % majority
   (`results/eda/metadata_shortcut.json`). A model can therefore gain a little from clip length. Mitigation: accuracy on padded vs full clips is reported for every model.
3. **Native sample-rate and bandwidth differ across clips** (8 to 192 kHz originals resampled to 16 kHz; clips originating at low sample rates have empty high-frequency bands, which the floor turns into the clamp value). 693 clips contain digital silence inside the real signal.
4. **AudioSet pretraining overlap.** The AST checkpoint was fine-tuned on AudioSet (YouTube audio, with classes such as dog, siren, jackhammer, engine). AST therefore has an audio-domain pretraining advantage over the
   from-scratch models, and the ImageNet MobileNetV3 control does not equalise it. Whether any UrbanSound8K source material appears in AudioSet was not checked.
5. **The pretraining control is confounded:** the ImageNet MobileNetV3 differs from the scratch one in initialisation and learning rate (3e-4 vs 1e-3), and ImageNet weights expect natural-image statistics, not log-mel input.
6. **Two front-ends** (log-mel vs Kaldi fbank) and different normalisation (training-fold statistics vs checkpoint constants), batch size and learning rate between AST and the rest. (SpecAugment durations were equalised in seconds, D-36, so that is no longer a difference.)
7. **Single seed (42).** Standard deviations are across folds (different data), not across seeds; no confidence intervals over initialisation randomness. Fold means are unweighted although folds differ in size (806 to 990 clips).
8. **Validation fold is small** (about 800-990 clips, roughly +/-1.5 points of sampling noise per epoch), and best-epoch selection on it is noisy; validation accuracy is optimistically biased as a selection criterion (the test fold is not).
9. **Class imbalance** (gun_shot 374, car_horn 429, siren 929) is not corrected in the loss; macro-F1 is reported alongside accuracy.
10. **Weight decay on all parameters** (biases, norms) and no class weighting: simple defaults, not tuned.
11. **Latency caveats (not yet measured):** Apple M5 (4 performance + 6 efficiency cores), no CPU affinity control, so thread counts are not tied to core types and multi-thread numbers are noisy; Apple silicon is not an edge-device CPU; PyTorch's int8 kernels (qnnpack) on this Mac were
    measured about 7x **slower** than fp32 for AST in a random-weight probe (702 ms vs 98 ms, one thread), so quantization may shrink models without speeding them up here. The ONNX Runtime comparison exists to show the deployment-style picture.
12. **The CRNN uses a bidirectional GRU**, which needs the whole 4 s window; it is not a causal/streaming design.
13. **Literature numbers** in the old interim table were unverified; see `REFERENCES_VERIFIED.md`.
14. **Compute/time:** results come from one run per fold on one machine; AST may be reported on a subset of folds if time runs out (fold order 1,5,9 first), in which case every table says so.
