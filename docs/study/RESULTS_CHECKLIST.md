# Results checklist: what the report and presentation need, and where each item comes from

Pointers and facts only (no report prose). Requirements are quoted from `ICT_4442_Mini_Project_Guidelines.pdf` (sections 3-5) and the synopsis.
All tables/figures are generated from result files; regenerate with:

```bash
.venv-post/bin/python scripts/compute_complexity.py        # results/complexity.json (params, MACs); already committed, rerun only if models change
.venv-post/bin/python scripts/make_tables.py               # results/tables/*.{csv,md}, results/figures/*.png (v2 results only)
# or, after the post-training stages:  .venv-post/bin/python scripts/run_post.py --stage tables
```

The final numbers are collected, with their source files and fold counts, in `docs/study/RESULTS_NUMBERS.md` (generated by `scripts/make_numbers_sheet.py`; regenerate after any change).

Never copy a number from a doc into the report: read it from `results/tables/*.csv` (they state how many folds each row has).

## 2. Minimum set (report) and suggested set (10-12 minute presentation)

**Report, must have**

1. Master comparison table: `results/tables/master_comparison.md` (accuracy, macro-F1, params, size, MACs, latency; "Folds" column; if AST has fewer than 10 folds it says so).
2. Confusion matrices per model: `results/figures/confusion_<exp>.png` (or `confusion_grid.png` for one figure) + `top_confusions.md`.
3. Per-class F1 across models: `per_class_f1.png` / `.md`.
4. Compression results: `quantization.md`, `pruning.md`; efficiency: `latency.md` (with the machine metadata and caveat from `results/latency/latency.json`).
5. Protocol description: factsheet s1-s2 (data pipeline, split rule, training protocol v2, metrics definitions).

**Presentation, suggested (each is one slide)**

1. Task + data + split rule (`results/eda/class_counts.png`, `fold_class_counts.png`).
2. The accuracy-efficiency picture: `accuracy_vs_params.png`, `accuracy_vs_macs.png`, `accuracy_vs_latency.png` (the last exists only after latency has been run).
3. Master table (as an image or table).
4. Error analysis: `confusion_grid.png` + `top_confusions.png`.
5. One compression slide: quantization size/accuracy/latency (PyTorch vs ONNX Runtime) and pruning.
6. Limitations (3 bullets from factsheet s5).

## 3. Extra analyses worth showing (given what was found while building)

| Analysis | Why it matters (fact) | Where it comes from |
|---|---|---|

| **MACs vs parameters** | CNN baseline: 0.39 M params but 361 M MACs; MobileNetV3-S: 1.53 M params but 28.6 M MACs; CRNN 0.56 M / 266 M; AST 85.6 M / 44,083 M. Parameters do not rank models by compute | master table; `accuracy_vs_params.png` vs `accuracy_vs_macs.png`; `results/complexity.json`; generated layer tables `docs/study/generated/model_summaries.md` |
| **Quantization: size vs latency are different findings** | size ratios from dry runs were ~3.9x (CNN), ~3.5x (MobileNetV3-S), ~3.9x (AST); in a random-weight probe PyTorch dynamic int8 AST was ~7x **slower** than fp32 on this Mac (702 vs 98 ms, 1 thread). To be confirmed (or not) by the real latency run, not to be quoted from the probe | `results/tables/quantization.*` (size, accuracy) and `latency.*` rows `fp32_torch` vs `torch_dynamic_int8` vs `onnx_fp32` vs `onnx_int8`, 1T and 4T |
| **Pretraining control and its caveats** | MobileNetV3-S scratch vs ImageNet isolates ImageNet pretraining but also changes lr (1e-3 vs 3e-4) and uses image weights on log-mel; AST also has AudioSet pretraining | master-table rows for the two MobileNetV3 runs and AST; the `[Ablation A-1]` row (scratch at lr 3e-4, D-38) separates initialisation from learning rate; caveats: factsheet s5 items 4-5, viva prep s C |

## 5. Before you quote any number

1. `git status` clean and `git log` shows the result commits ("Add results (protocol v2, real runs): ...").
2. The `Folds` column says 10/10 (or the AST subset you intend to disclose).
3. Latency rows exist only after the manual latency stage (needs the idle machine); until then those cells are "-".
4. Check one AST result file after the handover: `results/ast/fold1.json` should show `config.specaugment.time_width = 40` and a commit that contains D-36 (RUNBOOK s0b).
